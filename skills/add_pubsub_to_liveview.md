# Skill: Add PubSub Real-Time Updates to a LiveView

## Purpose

Make a LiveView list page update in real-time across all connected clients when records are created, updated, or deleted. Uses Phoenix PubSub (already included in every Phoenix project) — no extra dependencies needed.

## Prerequisites

- A context module with CRUD functions (e.g., `Psc.Blog` with `list_posts/0`, `create_post/1`, etc.)
- A LiveView that uses streams to display a collection (e.g., generated by `mix phx.gen.live`)
- The app's PubSub server is running (default: `Psc.PubSub`, started in `application.ex`)

## Steps

### 1. Define a PubSub topic in the context module

Add helper functions for subscribing and broadcasting at the bottom of the context module:

```elixir
# lib/psc/<context>.ex

# -- PubSub --

@topic "<resource_plural>"

def subscribe do
  Phoenix.PubSub.subscribe(Psc.PubSub, @topic)
end

defp broadcast({:ok, record}, event) do
  Phoenix.PubSub.broadcast(Psc.PubSub, @topic, {event, record})
  {:ok, record}
end

defp broadcast({:error, changeset}, _event) do
  {:error, changeset}
end
```

Replace `<resource_plural>` with the actual resource name (e.g., `"posts"`, `"comments"`).

### 2. Broadcast from context mutation functions

Pipe the result of `Repo.insert/1`, `Repo.update/1`, and `Repo.delete/1` through `broadcast/2`:

```elixir
def create_post(attrs \\ %{}) do
  %Post{}
  |> Post.changeset(attrs)
  |> Repo.insert()
  |> broadcast(:post_created)
end

def update_post(%Post{} = post, attrs) do
  post
  |> Post.changeset(attrs)
  |> Repo.update()
  |> broadcast(:post_updated)
end

def delete_post(%Post{} = post) do
  post
  |> Repo.delete()
  |> broadcast(:post_deleted)
end
```

### 3. Subscribe in the LiveView's `mount/3`

In the **Index** LiveView, subscribe when the socket is connected:

```elixir
def mount(_params, _session, socket) do
  if connected?(socket), do: Blog.subscribe()

  {:ok,
   socket
   |> stream(:posts, Blog.list_posts())}
end
```

### 4. Handle PubSub messages in the LiveView

Add `handle_info/2` clauses for each event:

```elixir
@impl true
def handle_info({:post_created, post}, socket) do
  {:noreply, stream_insert(socket, :posts, post, at: 0)}
end

@impl true
def handle_info({:post_updated, post}, socket) do
  {:noreply, stream_insert(socket, :posts, post)}
end

@impl true
def handle_info({:post_deleted, post}, socket) do
  {:noreply, stream_delete(socket, :posts, post)}
end
```

## Notes

- `stream_insert/4` with `at: 0` prepends new items; without it, items are appended or replaced if they already exist in the stream.
- If the LiveView tracks an empty-state assign (e.g., `@posts_empty?`), update it in the `handle_info` callbacks as well. Streams are not countable, so you need a separate assign for that.
- If the context functions accept a `current_scope` as the first argument, make sure `subscribe/0` and `broadcast/2` still work correctly — you may want scoped topics like `"posts:#{scope.user.id}"` for user-specific data.
- For scoped topics, pass scope to subscribe: `subscribe(scope)` → `Phoenix.PubSub.subscribe(Psc.PubSub, "posts:#{scope.user.id}")`.

## Example: Scoped PubSub (user-specific data)

```elixir
@topic_prefix "posts"

def subscribe(%Psc.Scope{user: user}) do
  Phoenix.PubSub.subscribe(Psc.PubSub, "#{@topic_prefix}:#{user.id}")
end

defp broadcast(%Psc.Scope{user: user}, {:ok, record}, event) do
  Phoenix.PubSub.broadcast(Psc.PubSub, "#{@topic_prefix}:#{user.id}", {event, record})
  {:ok, record}
end

defp broadcast(_scope, {:error, changeset}, _event) do
  {:error, changeset}
end
```

Then call `broadcast(scope, result, :post_created)` from your context functions that receive scope.
