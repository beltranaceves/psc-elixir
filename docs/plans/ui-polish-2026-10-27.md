## 1 — Centre row names in the canvas editor

**Observed.** The row-label column is sized to its longest label and the text is
left-aligned, so a narrow column leaves the label hugging the left border while the
cells around it are visually centred. The read-only label and the Edit-structure input
should share one alignment.

**Change.** `Grid.grid/1` centres both the read-only row label and the row-label input
(`text-center`, with the truncation `title` still carrying the full value).

**Check.** Existing grid/row-label tests still pass; the label column width calculation
is untouched.

## 2 — Cell snippet links autoscroll

**Observed.** An agent answer links a cell as `/canvas/<id>?tab=editor&cell=<key>`. The
handler opens the Editor tab and rings the cell, but on a phone (and on a long desktop
grid) the ringed cell can sit outside the viewport, so the link appears to do nothing.

**Change.** `Cell.card/1` exposes `data-cell-focused`. `CellFocus.updated/0` scrolls the
cell into view when it becomes the focused cell (and on mount for a deep link). The
scroll is vertical *and* horizontal, honours `prefers-reduced-motion`, and is skipped
while the tab panel is hidden.

**Check.** The existing `?cell=` test keeps passing; the hook is the only new client
behaviour.

## 3 — Mobile "Add references" form

**Observed.** The upload card lays the two file pickers and **Add to references** out in
one wrapping flex row. On a phone their widths are uneven and the primary action wraps
mid-row.

**Change.** The card title gets its own row; the actions become a one-column grid on
phones and a three-column grid from `sm` up, so each control is full width and the
primary action is last.

**Check.** `agent_config_live_test` still exercises the pickers and the merge action.

## 4 — Focus ring on the canvas name/description

**Observed.** The editor toolbar's name field and the Info tab's name/description use a
transparent border that becomes a coloured underline or a 1 px border on focus. The
catalog search field uses a softer, inset ring; the two surfaces read as different
products.

**Change.** Reuse the catalog search field's treatment (`focus:border-primary/50`,
`focus:ring-2 focus:ring-primary/35`, `focus:ring-inset`, `focus:outline-none`) in
`Header.title_field/1` and the Info tab's name and description fields, with the same
`bg-base-200` surface.

**Check.** Field ids (`canvas-name-form`, `canvas-info-name`, `canvas-description-form`)
are unchanged, so the LiveView and Playwright tests keep finding them.

## 5 — Presence, status pill and Share in the desktop agent bar

**Observed.** The Agent tab renders the generic header row above the panel with the
presence/status/Share cluster, leaving the agent's own top bar with only chat controls.
The cluster is far from the surface it describes and consumes a separate row.

**Change.** `AgentPanel.panel/1` accepts `presence`, `status` and `can_share?` and renders
the shared `Header.canvas_status/1` in its top bar from `sm` up. The top bar wraps if a
tablet cannot fit the title, the status cluster and the chat controls on one line. The
generic header row is skipped on the Agent tab while a chat is open; the start screen (no
session) keeps it. Phones keep the existing compact cluster in the app header.

**Check.** `header.ex` ids (`canvas-presence`, `canvas-save-state`, `share-canvas-button`)
are reused, so the presence/share tests keep their hooks, and there is exactly one instance
at every breakpoint.

## 6 — Subtle agent status above the composer

**Observed.** While a turn runs, the transcript shows a large "thinking" bubble with
bouncing dots at the bottom of the chat. It reads as a message even though it is a
transient status, and it pushes the transcript around.

**Change.** Remove the transcript bubble. Render `agent_phase` as one line of small,
low-contrast text with a pulsing dot directly above the composer. The
`#canvas-agent-status` id moves with it.

**Check.** The LiveView test hooks on the composer are unchanged; no test targets the
bubble.

## 7 — Send button geometry

**Observed.** The send button is `size-9` with `mb-1` inside an `items-end` row, so its
bottom edge floats 4 px above the textarea's bottom edge even though both are 36 px tall.
The input is visually rounded by the composer wrapper, while the button uses a different
radius.

**Change.** Drop the bottom margin, give the button the same `rounded-xl` radius as the
textarea, and size it to the composer's inner height (`h-12`: the 62 px box minus its 6 px
padding and 1 px borders) instead of a 36 px square. The stop button follows the same
geometry.

**Check.** Visual only; the form and its ids are unchanged.

## 8 — Ctrl/Cmd+Enter submits

**Observed.** The composer's `keydown` handler only treats plain Enter as submit; the
hint says "Enter to send".

**Change.** The handler submits on Enter or Ctrl/Cmd+Enter (still ignoring Shift+Enter and
IME composition). The hint line is removed entirely: the composer keeps that space,
especially on mobile.

**Check.** No server change; the existing form submit path is reused.

## 9 — Image-board designer cells on narrow viewports

**Observed.** A designer cell's header packs the size label, move grip, label input, kind
toggle, accent swatch and remove button in one non-wrapping row. A narrow placement (or a
narrow viewport, since placements are percentages) makes the row wider than the cell, and
the buttons paint outside the dashed footprint.

**Change.** The absolutely positioned editor card gets `overflow-hidden`, and its header
becomes `flex-wrap` with a `basis` on the label field. Controls now wrap *inside* the
cell; the card can still grow downward with its fields, which is the designer's existing
behaviour for small placements.

**Check.** `image_designer_test` still drives move, resize, kind, accent and field
controls by id.

## 10 — Wider Info settings column

**Observed.** The Info panel is capped at `max-w-2xl` at every viewport, so a tablet or
desktop leaves most of the workspace empty while the agent-config form is cramped.

**Change.** Make the cap viewport-based: `max-w-2xl` on phones, growing to
`md:max-w-3xl`, `lg:max-w-4xl`, `2xl:max-w-5xl`. It stays centred.

**Check.** Layout-only.

## 11 — Smaller rendered Markdown

**Observed.** Notes and file previews render at the prose default (16 px), and canvas
cells at `prose-sm` (14 px), which is dense enough to crowd the grid.

**Change.** `.markdown-preview` (the shared rendered-Markdown surface) uses 14 px; the
canvas cell renderer uses 13 px. Headings keep their existing cell-specific scale.

**Check.** CSS-only; the cell prose rules already override the typography plugin.

## 12 — Show reference files the agent read

**Observed.** A `read_agent_file` tool call appears as a collapsible JSON blob, and its
file ref renders in the same undifferentiated chip row as note/template refs. A reader
cannot tell at a glance which documents the answer was based on.

**Change.** Give file refs their own block in the assistant message — a small "Read files"
label plus one row per path, with a document icon and a link to the Info tab. Notes and
templates keep the chip row; files are removed from it to avoid duplication.

**Check.** `read_file` already returns `Ref.file/3`, so no tool or server change is
needed.

## 13 — Carousel arrows everywhere

**Observed.** The canvas library's template carousel buttons are `lg:hidden`. The hook
already hides each arrow when the strip cannot scroll in that direction, so the gating is
redundant and tablets/desktops lose the affordance.

**Change.** Drop `lg:hidden` from both buttons. The hook's visibility logic is unchanged.

**Check.** The colocated hook is still the only behaviour; no markup id changes.

## 14 — Preserve subsection order when instantiating a template

**Observed.** A template stores a cell's field order as the `"fields"` list, but
instantiation turns each field into a map key on the canvas cell. Postgres `jsonb` (and
Elixir's small maps) do not preserve insertion order — small maps iterate sorted — so the
canvas shows subsections alphabetically instead of in the authored order.

**Change.** Canvas cells gain a reserved `"field_order"` list. Instantiation copies the
template's `"fields"` order into it; `add_cell_field` appends and `remove_cell_field`
removes; `Structure.field_names/1` returns the stored order and falls back to map order
for canvases created before the key existed. `Cell.card/1` iterates that list. The key is
reserved so it can never be added or rendered as a field.

**Check.** New test in `canvas_test.exs` asserts the instantiated order and that
add/remove keep it; the existing bento assertion that `"fields"` is not copied still
holds (the canvas key is `"field_order"`).
